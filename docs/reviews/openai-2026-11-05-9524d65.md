Major, app/controllers/issue_recurrences_controller.rb:12-16
N+1 queries loading template issues on the project tab
Problem: index builds the template list with @recurrences.map(&:issue).uniq. Unless :issue is already eager-loaded, this triggers one SELECT per recurrence to fetch its issue. With many recurrences this becomes N+1 and slows the page.
Failure scenario: A project with 200 recurrences causes ~200 extra queries to load the associated issues before computing @series, leading to slow requests and timeouts under load.
Fix: Eager-load the association and/or avoid per-row loads. For example:
  @recurrences = @project.recurrences.includes(:issue).select {|r| r.visible?}.sort_by {|r| [r.issue_id, r.id]}
  templates = Issue.where(id: @recurrences.map(&:issue_id).uniq)
  series = IssueRecurrenceSeries.for_templates(templates)
  @series = @recurrences.uniq(&:issue_id).to_h { |r| [r.id, series[r.issue_id]] }

Minor, lib/issue_recurring/issues_helper_patch.rb:10-16 and app/views/issues/_issue_recurrences_hook.html.erb:5
Wrong sprite icon name for delete action; icon not rendered on Redmine 7
Problem: sprite_icon('del', ...) is used for delete buttons. Redmine’s SVG sprite defines 'delete', not 'del'. The helper will emit an <svg> referencing '#del' which doesn’t exist, so the glyph is missing even though the link works.
Failure scenario: On the issue panel and in the recurrences list, the delete link shows no icon (empty space), confusing users and failing visual QA; tests that only assert presence of an <svg> won’t catch it.
Fix: Use the correct sprite name:
  link_to sprite_icon('delete', l(:button_delete)), ...
Also consider keeping the previous label fallback if you need to tolerate older cores, but on Redmine 7 just switching to 'delete' is sufficient.
