Major, lib/issue_recurring/issue_patch.rb:34-41
drop_recurrences_not_manageable requires both view_issue_recurrences and manage_issue_recurrences to retain copied recurrences. This unnecessarily drops recurrences even for users who are allowed to create/manage them but (mis)configured without the view permission.
Failure scenario: In a project where the role has manage_issue_recurrences but not view_issue_recurrences (permissible in Redmine’s permission model), with Setting.plugin_issue_recurring[:copy_recurrences] = true, copying an issue will silently remove all recurrences on the new issue due to the before_validation hook, despite the user having the manage permission needed to create them.
Fix: Only require manage_issue_recurrences to allow keeping/copied recurrences. For example:
  return if recurrences.empty?
  return if User.current.allowed_to?(:manage_issue_recurrences, project)
  self.recurrences = []

Resolution: changed in 3e3c0a3, not as proposed. Keeping the recurrences with manage permission alone
would bring the failure back: their create validation (IssueRecurrence#editable?) requires view and
manage permission and that the user may edit the issue, so the copy would again be refused with
"Recurrences is invalid". The finding showed that the hook only partly repeated that check (edit
permission missing); it now selects the copied recurrences with editable? itself. Test:
test_copying_issue_without_edit_permission_copies_no_recurrences (fails without the change).
